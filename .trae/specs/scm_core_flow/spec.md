# 供应链管理教学工具 - 核心业务流程修复与增强规格文档

## Overview
- **Summary**: 修复供应链管理教学工具的核心业务断点，实现从订单到交付的完整数据流转，包括采购入库、生产入库、销售库存扣减、质量检验和基础财务管理功能。
- **Purpose**: 解决当前系统中采购物料无法入库、完工产品无法入库、销售库存不联动、质量无法管控等严重问题，确保系统能够真实模拟供应链管理的完整业务流程。
- **Target Users**: 使用该教学工具进行供应链管理学习的学生和教师。

## 目标
- 实现采购入库功能，完成采购到入库的完整闭环
- 实现生产入库功能，完成生产到入库的完整闭环
- 实现销售库存自动扣减，确保库存数据实时准确
- 增加基础质量检验功能，覆盖来料检验(IQC)和成品检验(OQC)
- 增加库存流水记录，实现库存收支存的完整追溯
- 增加基础财务管理模块，包括应收应付和简单成本核算
- 保持现有功能稳定，不破坏已实现的手机适配

## 非目标
- 不重构整个系统架构
- 不引入新的技术栈
- 不实现完整的ERP系统功能
- 不实现复杂的权限管理系统

## 背景与上下文
当前系统存在以下核心业务断点：

### 已实现的模块
1. 基础资料管理（产品、物料、供应商、客户、BOM）
2. 生产计划管理（含甘特图）
3. 采购计划管理（需求计算、订单管理）
4. 库存管理（物料/产品库存、预警、分析）
5. 需求预测（销售预测、需求分析）
6. 物流配送（运输方式、配送计划、货物跟踪）
7. 客户服务（沟通记录、售后工单、满意度管理）
8. 数据分析（性能指标、成本分析）
9. 手机适配（响应式设计）

### 发现的业务断点
1. **采购入库断点**：采购订单完成后无法入库，物料库存不更新
2. **生产入库断点**：生产工单完成后无法入库，产品库存不更新
3. **销售库存断点**：订单确认后不扣减库存，导致库存数据不准确
4. **质量检验缺失**：采购和生产环节都没有质量检验功能
5. **库存追溯缺失**：无库存流水记录，无法追溯库存变化原因
6. **财务管理缺失**：无应收应付、成本核算功能

## 功能需求

### FR-1: 采购入库功能
- **FR-1.1**: 在采购订单详情页增加"确认入库"按钮
- **FR-1.2**: 入库时支持部分入库，可输入实际入库数量
- **FR-1.3**: 入库成功后自动更新物料库存（增加库存数量）
- **FR-1.4**: 生成库存流水记录，记录入库明细
- **FR-1.5**: 可选择是否需要进行来料检验

### FR-2: 生产入库功能
- **FR-2.1**: 在生产工单详情页增加"确认完工"按钮
- **FR-2.2**: 完工入库时支持部分入库，可输入实际入库数量
- **FR-2.3**: 入库成功后自动更新产品库存（增加库存数量）
- **FR-2.4**: 自动扣减生产所用物料的库存（按BOM计算）
- **FR-2.5**: 生成库存流水记录，记录入库和出库明细

### FR-3: 销售库存扣减
- **FR-3.1**: 在订单确认时自动检查产品库存是否充足
- **FR-3.2**: 库存充足时自动扣减产品库存
- **FR-3.3**: 库存不足时提示用户并阻止确认
- **FR-3.4**: 生成库存流水记录，记录销售出库

### FR-4: 质量检验功能
- **FR-4.1**: 新增质量检验模块，包含IQC和OQC
- **FR-4.2**: 采购入库时可选择先进行来料检验
- **FR-4.3**: 生产完工入库前进行成品检验
- **FR-4.4**: 检验记录包含：检验数量、合格数量、不合格数量、检验人、日期
- **FR-4.5**: 检验不合格可选择：退货、让步接收、报废

### FR-5: 库存流水功能
- **FR-5.1**: 新增库存流水数据实体
- **FR-5.2**: 记录所有库存变化：采购入库、生产入库、销售出库、生产领料、盘盈盘亏
- **FR-5.3**: 每条流水包含：类型、业务来源、数量、日期、操作人
- **FR-5.4**: 在库存管理页面增加流水查询功能

### FR-6: 基础财务管理
- **FR-6.1**: 新增应收账款功能，记录销售订单应收款
- **FR-6.2**: 新增应付账款功能，记录采购订单应付款
- **FR-6.3**: 简单成本核算：根据BOM计算产品成本
- **FR-6.4**: 订单完成时自动生成应收款记录
- **FR-6.5**: 采购入库时自动生成应付款记录

## 约束

### 技术约束
- 基于现有Vue 3 + Bootstrap 5技术栈
- 使用LocalStorage进行数据持久化
- 不引入新的第三方库

### 业务约束
- 教学工具定位，功能以演示和教育为主
- 数据基于示例数据，不连接真实业务系统

## 假设
- 用户会按照标准流程操作：采购→入库→生产→销售
- 示例数据已包含足够的产品、物料、BOM信息
- 库存初始数据准确

## 验收标准

### AC-1: 采购入库功能
- **Given**: 存在一条采购订单，状态为"待入库"
- **When**: 用户点击"确认入库"并输入入库数量
- **Then**: 物料库存增加对应数量，订单状态更新为"已完成"，生成库存流水
- **Verification**: `programmatic` - 检查库存数据变化和流水记录

### AC-2: 生产入库功能
- **Given**: 存在一条生产工单，状态为"生产中"
- **When**: 用户点击"确认完工"并输入入库数量
- **Then**: 产品库存增加对应数量，物料库存扣减对应数量（按BOM），生成库存流水
- **Verification**: `programmatic` - 检查库存数据变化和流水记录

### AC-3: 销售库存扣减
- **Given**: 存在产品库存充足的销售订单
- **When**: 用户确认订单
- **Then**: 产品库存自动扣减，生成库存流水
- **Given**: 存在产品库存不足的销售订单
- **When**: 用户尝试确认订单
- **Then**: 提示库存不足，阻止确认操作
- **Verification**: `programmatic` - 检查库存扣减和提示信息

### AC-4: 质量检验功能
- **Given**: 需要进行来料检验的采购入库
- **When**: 用户选择"先检验后入库"
- **Then**: 创建IQC检验单，检验合格后才能入库
- **Verification**: `programmatic` - 检查检验单状态和入库流程

### AC-5: 库存流水功能
- **Given**: 存在库存变化的业务操作
- **When**: 操作完成后
- **Then**: 生成对应的库存流水记录
- **Verification**: `programmatic` - 检查流水记录完整性

### AC-6: 财务管理
- **Given**: 订单确认或采购入库
- **When**: 业务完成后
- **Then**: 自动生成应收/应付记录
- **Verification**: `programmatic` - 检查财务记录生成
